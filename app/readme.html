What this is

A self-contained nanoscale matter simulator that ships as three static worlds — a folding 3D periodic table, a chemistry lab with machine presets, and a cross-lab field engine — running entirely in the browser from plain ES modules. There is no build step, no package manager, no network at runtime: `three.js` r160 is vendored under lib/ and wired by an import map.

Run it

node serve.js          # → http://localhost:8082 (zero-dependency static server)
# or any static server over HTTP, because ES modules need http:
python3 -m http.server 8082
Landing hub: landing.html · lab: experiments.html?exp=salt · table: index.html · field engine: crosslab/physics_simulator.html · this page: readme.html.

SecMesh — measured results, comparable to products

Every percentage below was measured live on this device — no fabricated figures. The sender (mesh-tester.mjs) fires real TCP/UDP probes at a defended listener (mesh-guardian.mjs, "system ON") and at an identical undefended listener (mesh-control.mjs, "system OFF") on loopback, then counts what each side actually served. Re-measure any time:

node node-tests/bench-vectors.mjs --count 300 --rate 30 --reps 3 --out bench-vectors.json

Configuration: 300 probes × 5 vectors × 3 reps, sender at 30/s, linger held 6.5 s (longer than the 6 s idle-eviction window, so idle eviction is actually exercised).

Plain-English map — this box vs a different product

Think of the system as a bouncer at the front door; "system OFF" is the same building with the door propped open (a stock server with no firewall — everything gets in).

MeasuredWhat it meansSame mechanism in a product
syn-slew 42%Per-source pace rule: rush the door faster than the allowed rate and the excess is turned away.WAF rate limits · Apache/Nginx limit_req · Cloudflare per-IP throttling
linger 100% vs 0%"No standing in the lobby": idle connections are escorted out after the 6 s eviction window; a stock server holds them forever.Firewall / load-balancer idle timeouts (pfSense, HAProxy timeout client, F5-style session reaping)
udp-amp 50%UDP datagrams treated as noise: past the allow rate the system stops accepting, where a stock echo accepts 100%.DDoS UDP clamp / L3-L4 mitigation (Cloudflare, Arbor), DNS-amplification defense
snaplag ~8%The occasional over-speed rush gets rejected, but legitimate traffic is slowed by ~0 ms.The "does the security product slow my users down?" number

Introduce the system and it behaves like a small next-generation firewall / rate-limiting edge (pfSense + Suricata class, or Cloudflare rate rules) — rejecting about half of the attack traffic it's fed while adding ~0 ms of visible latency.

Where cryptography fits (SHA-256, TLS, the engine's quantum-crypto mode). Those are the data layer — the tamper-proof envelopes and key exchange that protect conversation contents (the physics engine even simulates a quantum-keys class of it). This benchmark is the admission layer — who gets through the front door at all. They do not compete: encrypted traffic still passes admission first, and swapping SHA-256 for another hash would move none of the numbers above. The table is about the door; crypto is about the safe inside.

Runtime architecture

        ├─ renderer           WebGL, preserveDrawingBuffer, low-power
        ├─ machines           UI cards + readouts (B · E · P · ☀ vs N atoms · ⇢ fed · auto)
        ├─ tracking           bonded-cluster overlay (face-tracker style) + tap → pinned popup

   crosslab/physics_simulator.html          # standalone Universe world (module script)
        ├─ SpatialMap / Sim     swarm + field engine, SecMesh sec-step (DOM-free, headless-testable)

                                per-defender paths through the data lattice (CFG.autoDefense)

The split is deliberate: exp-core.mjs is a plain module with no globals, so the whole physics can be validated headlessly. The lab ships a family of standalone probes that boot the code through the same node process (run.mjs, rate-probe.mjs, ui-stress.mjs, overlay-probe.mjs, scanning, settings, grid, parts, mods, mach-sweep, laser-probe, urlparam-test, exp-core-test …) to gate regressions.

Physics & data model — the honest approximations

LayerWhat's really computed
InteractionLennard-Jones pairwise + Coulomb for charge, cell-hashed neighbour lists.
ThermostatSoft; rate-scaled heating term + operating-point taper so °K ≈ real kinetic temperature at every speed.
BondingForm/break on geometry + energy; ionic / covalent / hydrogen colour-coded; excited states, reactions, radioactive decay.
FieldsConstant B (Lorentz), constant E, RF-style power, plus the collimated beam bank (ray / pulse / trap / flood).
Time scaleResolved fine-regime solver for chemistry band; coarse rate-consistent fast-forward; deep-macro single-substep up to 3.2 T y/step (PBD rigid bonds, renormalized thermo).

Exports land as processable JSON: aps-<exp>-<t>fs.json → { format, experiment, run, feed, atoms, bonds, events }. atoms are nm & nm/step, bonds index into atoms, and run carries rate, temperature, fields, the full beam bank, shape, feeder totals, and the cross-lab preset — see the guide §6 for the schema.

Use it — by hand or by agent

By hand (manual)
  • Open the lab; the ▦ command center lists every experiment → tap a dossier → DEPLOY.
  • Top bar: ▶/⏸ run, ↻ reset, ◎ tracking, −/＋ time-speed (the pill reads the exact Δ).
  • Top bar cluster ＋ spawns elements; ⚙ opens geometry / Chladni / scope / laser / machines+feeder / MRI / cross-lab. The MRI scanner docks itself under the top bar (flush left) and drags by the ≡ grip; clip saves a GIF + filmstrip PNG + manifest + a self-contained experiment report (-anim.html) — the full technical document with instrument captures, gray→hot imaging sheets, all four MRI channels and the written results.
  • ⚙ gear in the HUD (right edge) = settings: overlays, hud size, modules, save root, agent identity.
  • Full picture: guide.html.
By agent
  • Boot a target: experiments.html?exp=<id> (salt, melt, iron, rust, plasma, bubble, alloy, aero, slush, mine) skips drive-time.
  • Export state: ▦ → ⬇ export data writes experiments/aps-…-<t>fs.json under your save root.
  • Identify: ⚙ settings → agent names the export agents/<you>/… so work lands in one folder.
  • Inspect from JSON: atoms, bonds, events, run/beam config — no UI scraping needed.
  • Machine-read the doc set: README.md (short), guide.html (manual), readme.html (this), exported schema — all local, all plain text.
  • Headless checks: the engine is module-pure, so an agent can require exp-core.mjs and assert on new Chamber without a browser.

Agent walkthrough — a repeatable recipe

  1. Serve the folder. node serve.js (or any static HTTP server). Agents should read files from disk; a live page is only needed for a run.
  2. Pick a world. Periodic table → index.html · chemistry → experiments.html?exp=<id> · universe → crosslab/physics_simulator.html. Every experiment id/goal/step is exported from exp-core.mjs (EXPERIMENTS).
  3. Capture a baseline. Export before any change (⬇ export data) so the run object documents rate, fields and beams verbatim.
  4. Drive one knob at a time — heat, temp, B axis, beam axis/type, feeder schedule, shape — and re-export; the diff is the entire experiment state. Debugging a run is reading events[].
  5. Regression-gate changes. Re-run the headless suite (run / rate-probe / ui-stress / overlay-probe / settings / grid / scanning / parts / mods / mach-sweep / laser-probe / urlparam-test / exp-core-test). The lab is stable when all print *-OK.
