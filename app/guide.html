1 · Overview

An interactive nanoscale matter simulator: a folding 3D periodic table, a chemistry lab where you spawn elements, weld bonds, and hammer them with electromagnetic fields, a machine park (tokamak, stellarator, beamline, CVD, sputter), a live MRI-style tomography scanner, and a cross-lab field engine that turns the same chamber into atoms, cells, brains or galaxies — all running offline in your browser with no build step.

2 · Quick start

There is nothing to install. ES modules + an import map mean you open it over HTTP rather than file://:

node serve.js            # → http://localhost:8082
# or any static server:
python3 -m http.server 8082

Land on landing.html, or jump straight to experiments.html. The “▦ COMMAND CENTER” menu in the lab lists every experiment with its goal.

2b · Drive it — by hand or by agent

Every surface of the lab works the same whether a human taps it or an agent drives it, because state enters and leaves through the same plain interfaces.

By hand

  • ▦ command center → tap a dossier → DEPLOY. Then ▶ run, −/＋ pace time, ＋ spawn elements, ⚙ open the instruments drawer (machines, beams, MRI, cross-lab). The ⚙ gear on the right edge of the stats bar holds settings — overlays, hud size, modules, agent identity, save root.
  • Full control tour: Lab controls below.

By agent

  • Boot straight to a target: experiments.html?exp=salt (any id from the ▦ menu or the exported EXPERIMENTS list) skips drive-time navigation.
  • Export state, don't scrape the page: ▦ → ⬇ export data writes aps-<exp>-<t>fs.json with run/feed/atoms/bonds/events — rate, fields, beams, shape, feeder and full history are all plain JSON.
  • Name your work: ⚙ settings → agent sets the identity so exports land under agents/<you>/….
  • Verify without a browser: exp-core.mjs is DOM-free, so node can construct chambers and assert directly. The lab ships regression probes (run · rate-probe · ui-stress · overlay-probe · settings · grid · scanning · parts · mods · mach-sweep · laser-probe · urlparam-test · exp-core-test) — all green prints *-OK.
  • Drive the universe world: physics_simulator.html?preset=… boots straight to a scene; ⚒ export pulls run + structure + security as JSON; the SecMesh baseline is reproducible headlessly (node node-tests/secmesh-exp.mjs all).
  • The technical readme (readme.html) documents architecture, agent recipes and licence/credit references.

4 · Lab controls

Time scale — from 10 attoseconds to eons

The stepper covers 31 preset rates across a ± trillion-× range. The slow end resolves every bond wiggle in cinematic slo-mo; the fast end fast-forwards geological and even astronomical time:

BandRates (per frame)What it's for
Cinematic slow0.01 fs (10 as) → 0.5 fsZoom into every vibration, collision, and early bond-forming step.
Fine physics1 fs → 100 ps → 1 µsThe resolved spring-integrator regime where real chemistry is visible.
Fast-forward1 ms → 100 sMulti-substep coarse regime for long anneals and melts.
Deep macro17 min → 28 h → 116 d → 32 y → 3.2 ky → 0.32 My → 32 My → 3.2 Gy → 3.2 T yOne coarse PBD + renormalized-thermo substep per frame that still lands the full commanded time — run erosion over eons.
In the deep-macro band the readout is nanoseconds-accurate: the HUD time uses fs → ps → ns → µs → ms → s → min → h → d → y → My → Gy units, and the rate pill shows the exact per-step Δ. Everything is rate-consistent — the same commanded sim-time (per real frame) is delivered at every speed. One honest limit: after you have run tens of giga-years, floats can no longer represent single-femtosecond increments (adding 0.01 fs at 1e37 fs rounds to nothing), so if you slow back down the HUD correctly shows the time staying put — hit ↻ reset to start a fresh slow run.

Furnace & command center

The ▦ menu carries the furnace: heat (furnace power) and temp (target temperature) sliders, plus ⬇ export data. Fields readouts are split: B · E · P · ☀ live in the machine card; N atoms · ⇢ fed sits on its own line — field bars change fields only, never atom counts. A soft thermostat with a rate-scaled heating term and an operating-point taper holds temperature across speed changes, so the displayed °K is the real kinetic temperature.

Beam bank

In the instruments drawer (⚙) under the oscilloscope: add as many beams as you like, each aimed along any of the six directions (±X ±Y ±Z) with independent optics — ray steady heat + ionization, pulse ablation bursts, trap tweezers pulling atoms onto the line, flood wide soft illumination — plus power, spot width and per-type sliders (pulse frequency, grip strength). Each beam deposits momentum/energy only inside its own collimated spot cylinder, all dt-scaled so they stay rate-consistent. Counter-propagating pairs form an optical molasses that cancels net drift.

MRI scanner

A slice-tomography scanner for the live chamber (⚙ drawer; it also spawns docked under the top button bar, flushed to the left edge and dropped clear of the bar — ready the moment you open the lab). Arm it, pick the scanning plane, a signal (density atoms, therm kinetic energy, charge signed gradient, bonds bond density) and a colourmap (gray / hot), sweep the slice through the chamber. Sampling splats each atom over a Gaussian footprint so even sparse chambers read as smooth tomography. The virtual slice plane is shown as a glowing sheet inside the chamber. Drag it anywhere — grab the ≡ handle in the header (top-right) or the header itself — and it snaps to edges just like the other modules.

ALL-axis map & clip → animation

  • ALL (default) shows the X, Y and Z cross-sections side-by-side as one composite map — a full 3D picture in a single glance. Choosing X / Y / Z drops to that single slice.
  • ◧ MRI arms the live preview; ◈ snap re-samples at high resolution; ⬆ PNG exports the current view (or the clip filmstrip).
  • Clip mode (◌ clip): press once to record, again to save. It downloads a GIF89a of the sweep (the primary file) plus the PNG filmstrip, a frames manifest, and a self-contained <name>-anim.html experiment infocard — one full technical document pinned to the top of the screen: a 2×2 visual grid up front (a gray-colormap MRI clip, a chamber-scan frame, a square screenshot of the 3D environment, and a hot-colormap MRI clip), then scan figures from the other instruments — the chart recorder trace, the mass spectrum and the chamber manometer — plus imaging sheets of the axis sweep and the 360° orbital projection in both gray → hot colormaps, an MRI channels gallery that resolves the same slice on all four channels (density · therm · charge · bonds, each in gray and hot), a written experiment report (summary · interventions · imaging · results), a results-at-a-glance table, and below them every bit of run data: fields, temperature, laser & feeds, active beams, composition, the last events and the full raw JSON (🖨 save / print exports the whole document as a PDF). Zero dependencies; it opens in any browser.
  • One automatic download per save (Chromium/Brave throttle several at once) — the ⬇ gif · png · json · player chips under the scanner re-download any file with a normal click.
  • ◎ orbit rotates the projection through 36° view angles (the all-angles sweep).

Cluster tracking

A face-tracker-style overlay (top bar, on by default) that locks onto every bonded cluster — from a 2-atom pair up to a whole molecule — with colour-coded corner brackets and a Cn · formula chip glued to the atoms as they drift, merge, or split. Track ids persist via membership overlap; hover a bracket for a live report: composition, atom/bond counts, per-type bond distances vs rest length, and the local temperature.

Cross-Lab & cross wall

  • single — classic one-preset-at-a-time view with knobs + live preview.
  • stack — tick any combination of presets; the effective field is the max contribution per force, and removing a preset drops its forces cleanly.
  • ⬛ run cross wall — side-by-side A/B: every non-off preset gets its own independent chamber cloned from the exact same record of the first 44 live atoms (positions, velocities, temperature) and locked to the main speed stepper. Tap any tile to promote that regime back to the main chamber.

Moveable UI modules

Every major UI piece — the stats bar, the MRI scanner, the goal card, minimap, event feed and the tools sheet — is a module you can drag anywhere and snap back into the layout. The scanner spawns docked straight under the top button bar, flush to the left edge with a gap, so it's never hidden behind the action buttons.

  • Grab the ≡ grip (top-right corner of each module, now a full 34 px touch target) and drag, or press and drag the header/interior. The whole module moves as one group.
  • Edges snap to the viewport border and to the edges of other visible modules (within 10 px).
  • ⚙ Settings → modules lists every module with a checkbox toggle: unhide what you need, hide the rest, and dock the survivors edge-to-edge for a custom command deck.
  • Positions and toggles persist between sessions (per-browser).

Settings & overlays

  • minimap — live chamber density tile; spawns mid screen (~80px below centre); the rest of the page stays clickable underneath, drag it via its ≡ grip.

4c · AI & security — why the same engine does all three

The knobs of one simulator are the vocabulary of modern machine learning and security. Folded in from the gallery (crosslab/preview.html) so the whole story lives in this guide:

Graph Neural Networks

Nodes = neurons/atoms/galaxies. Edges = synapses/bonds/filaments. Message passing across the graph mirrors how the simulator propagates activation, entanglement and gravity. Training = adjusting edge weights (alignment force) to minimize energy.

Transformer Attention

Entanglement = attention weights. Every token attends to every other — non-local correlation. The entangle parameter tunes correlation decay with distance. Multi-head attention ≈ multiple entanglement channels.

Diffusion Models

Trail deposition + evaporation = forward/reverse diffusion. Agents deposit pheromone (score), diffusion blurs it (noise), chemotaxis follows the gradient (denoising). Slime mold solves the same variational problem as DDPM sampling.

Adversarial Robustness

Tunneling = adversarial escape. Particles quantum-tunnel through energy barriers — an adversarial example crossing a decision boundary in latent space. tunnel controls the barrier penetration rate: a direct robustness-testing knob.

Cryptographic Entropy

Wavefunction dynamics (quantum + entangle) inject the randomness that drives the key story. Wavefunction collapse on measurement = one-time pad generation; entangled pairs across nodes = device-independent QKD (Ekert protocol); decoherence rate = key expiration. (The planckScale label is a reserved UI knob — not wired.)

Anomaly Detection

Dark-energy repulsion (darkEnergy) pushes outliers into voids. Energy shells quantize normal behaviour into discrete levels. Anything between shells or stranded in a void = anomaly — the same shape as network-intrusion, fraud, side-channel detection.

Federated Learning

Nodes = clients. Alignment force = model averaging; repulsion = personalization (prevent collapse to the global model); curvature = non-IID data geometry. The simulator visualizes convergence dynamics across heterogeneous clients.

Zero-Trust Topology

Connections form only above a trust threshold (connectionThreshold); entanglement = shared secrets; tunneling = covert-channel risk. The graph structure is the policy — visualize, audit and harden it in real time.

4d · SecMesh — the security-system demo, moving targets

Turn on Security demo (⚙ → Security System; fire extra waves with ⟠ Attack burst) and the node graph becomes a network under a DDoS siege: attackers seek out and stress nodes, defenders intercept them, the firewall heals degraded nodes back to harmony, and a burst timer delivers deterministic DDoS waves. ⚒ Export then prints this run against a 69-trial baseline.

Baseline (docs/secmesh-concept.md)

  • 42/42 trials intrusion-free across the main matrix (threat 0.05→0.5, defenders 2→24, firewall 0.3→0.9, batches 10→80) with availability 1.000 and 15,855 attackers neutralized.
  • Overload boundary: first degradation only near 14× the baseline threat, then continuous, bounded and self-healing — no cliff.
  • Defense decomposition @ threat 0.35: the healing field is load-bearing; the full mesh adds another ~42% peak-stress reduction (no-defense 2/3 trials breached).
  • Fleet scale: the same 6-defender fleet stays clean from 60 → 360 nodes.

Moving-target auto-defense (A)

Enable Moving-target defense and the controller rotates defense strategy on a timer. Each strategy is a different decision rule over the same live data, and defenders never retrace a route:

  • sweep — every defender patrols on its own wholly unique path through an 8³ volumetric lattice of the field data (low-discrepancy, seeded per agent — no two share a route) and intercepts only at close range; the panel shows path cover (fraction of the volume visited).
  • perimeter — defenders hold the backline, engaging only attackers closing on the core.
  • rash — aggressive dash with a high kill rate at the cost of wider exposure.
  • pursuit — the base nearest-attacker hunt.

↻ rotate now (or press A to toggle the system) forces a rotation; the export card records strategy, rotation count, number of unique paths, % cover and close-range intercepts. Reproduce the whole baseline matrix with node node-tests/secmesh-exp.mjs all (writes JSONL per group into node-tests/secmesh-runs/).

4f · Real device testing — system ON vs system OFF

The console only shows attacks that a verified agent reports, so the fastest way to see one is to launch the suite on your own devices (node-tests/):

  • mesh-guardian.mjs (the system, device B) — listens on TCP --listen 7171, serves CORS-open JSON at --status 7172. Per-source rate-limit → syn-slew blocked, live-connection cap → slew-overload, idle keep-alive eviction → conn-linger, clean keep-alives echoed (snaplag accepted), optional UDP echo for udp-amp. No kernel/firewall claims — this is the userspace differential you own.
  • mesh-tester.mjs (attacker, device A, does not run the system) — vectors syn-slew, snaplag, udp-amp, pscan with --rate/--count; classifies served vs repelled by whether the target actually answers, prints VERDICT GUARD|BASELINE engaged X/Y (Z%). Refuses non-private targets unless --force.
  • mesh-control.mjs (system OFF) — identical wire surface, accepts everything, for the baseline leg.
  • One-device proof: node node-tests/mesh-selfcheck.mjs runs guardian vs baseline on 127.0.0.1 and passes when repel(guardian) > repel(baseline) (recent run: 31% vs 0%; the full 5-vector bench below reads 50.1% vs 0%).

Console tip: put the guardian URL (e.g. http://<device-B>:7172/status) in ◸ test suite → Agent, and the red probes stream onto the globe as they're blocked.

Plain-English map. Think of the system as a bouncer at the front door; "system OFF" is the same building with the door propped open (a stock server with no firewall — everything gets in): syn-slew = a per-source pace rule that turns away the excess of an over-rush (like Nginx limit_req / Cloudflare per-IP throttling); linger = "no standing in the lobby" — idle connections are escorted out after the 6 s window where a stock server holds them forever (like HAProxy timeout client / firewall session reaping); udp-amp = UDP datagrams treated as noise, past the allow rate the system stops accepting where a stock echo accepts 100% (Cloudflare / Arbor L3-L4 clamp style). So introduce the system and it behaves like a small next-gen firewall / rate-limiting edge — rejecting about half the attack traffic it's fed while adding ~0 ms of visible latency.

Where crypto fits (SHA-256, TLS, the engine's quantum-key mode) — that's the data layer: envelopes and key exchange that protect conversation contents. This benchmark is the admission layer: who passes the front door. They don't compete, and the numbers above wouldn't move if you swapped the hash — the table is about the door, crypto about the safe inside.

4g · Entanglement fabric — the quantum-key cluster

An E91 (Ekert) protocol simulator that can actually run on your phones as a cluster. Real photon entanglement can't travel over a wire, so — exactly as the physics engine is an honest approximation of matter — the quantum channel is emulated: the classical outcome distribution is sampled from the singlet joint distribution once both measurement settings are fixed, the only injection that breaks the Bell correlations is an eavesdropper's disturbance, and the Bell-CHSH test decides the verdict. Each node genuinely generates/measures its share and holds half the state.

  • Topology: complete-graph mesh — with N peers you get n(n−1)/2 links, each link one E91 session (initiator = lower-index peer, responder = higher-index). Every pair runs concurrently (async); a conference key is derived by hashing the honest link keys. Add a node and the mesh re-wires itself — nothing says "four" in the protocol.
  • Measurements: honest links hold Bell-CHSH S ≈ 2·√2 ≈ 2.83 (> 2, no eavesdropper) and derive a real SHA-256 key; inject --eve node-<k> and the links touching that node collapse to S ≈ 0.6 < 2 and ABORT — eavesdropping is detected, key refused. Gate: node node-tests/qkd-selfcheck.mjs (part of selfcheck.mjs). Measured 5-node proof (qkd-run.json, 4000 rounds): all 10 links KEY — S = 2.68–2.93 across the complete graph, 417–456 key bits per link, single conference key derived from the honest keys only, gate all green (ok/honOk/eveOk).

Control node: any always-on machine can drive the whole fabric — run qkd-cluster.mjs there with --peers (phones over wifi) or --adb all with the phones plugged in by USB, and it provisions, meshes, and tears down every node. The console is just another control surface: point its mesh field at that node's /e91 status ports.

Console streamdeck (⚙ → Security demo → ⟠ Entangle): the Entanglement fabric deck row — ⟠ arms, ⇆ rotates the round, ⚑ Eve arms the disturbance watch, ⌬ re-derives the conference key. Set the N peer /e91 URLs in the test suite's mesh field (defaults to the host supervisor's census-family status ports 127.0.0.1:20003 / 20006 / 20009 / 20012 / 20015 — peer i = 20003 + 3i). On the world, each reachable peer appears as an orbiting mini-sphere joined by constellation links — green for honest KEY links, red for Eve ABORTs — so a full deployment reads as a map of every sphere working together at a glance. Under the deck, a live per-link readout shows the raw telemetry for each link — KEY/ABORT · S (Bell-CHSH) · initiator/responder role · rounds · key bits (e.g. 336 bits) · wire target · full derived key — plus a summary line (peers · links · honest · aborts · S̄ · Σ bits · conference fingerprint). So the constellation is the picture and the readout is the receipt. Mesh Key only lights when the hash of the honest keys derives cleanly. Bench ⟳ (input next to the deck) is the ramp-up control: it POSTs /bench?n=<rounds> to every peer, and each re-runs the links it initiates at your length — longer runs ⇒ proportionally more bits (bits ≈ n/9 per link, since each side picks base 0/1/2 and both align ≈ 1/9 of the time); the secret actually shared is the SHA-256 of those corrected bits. Same S̄ at any length — the proof operator is length-independent. This is the data layer — sibling to the admission numbers above, not a competitor to them.

5 · The physics (honest approximations)

  • Lennard-Jones pairwise forces + Coulomb for charged species, cell-hashed neighbour lists.
  • A soft thermostat with a rate-scaled heating term and an operating-point taper so the furnace holds temperature across speed changes.
  • Chemical bonds form/break on geometry + energy; ionic, covalent and hydrogen colour-coded. Excited states, reactions and radioactive decay are in.
  • Machine fields: constant B (Lorentz), constant E along a set direction, and input power (RF-style heating), plus the beam bank described above.
  • A resolved fine-regime solver for the chemistry band, a coarse rate-consistent fast-forward regime, and a deep-macro single-substep band that delivers every tick up to 3.2 T y/step at full sim-time per frame (rigid bonds via PBD, dt-scaled event rates, renormalized thermo so the °K readout stays truthful).
