The long version — the arc

23.5 years ago I was a C++ student teacher. The discipline that defines this repository was born in that classroom: I made students write literal C++ on paper, in pencil, before they were allowed anywhere near a compiler. That is worth saying out loud, because it is exactly the discipline this repository runs on: design first, express it plainly, then let the machine verify.

Then reality did what reality does. The last twenty-plus years were spent in retail management, fast food, odd jobs, and construction — a long detour that had nothing to do with compilers, classes, or anything on that paper.

In March 2026 I watched an LLM genuinely write code for the first time and realized the floor had moved: the gap between "an idea and a working program" had collapsed to something one determined person could cross. I started shipping immediately. The GitHub account below (handle: BoogerCheeseOnRye) shows the sprint: fifteen public repositories in roughly five months, beginning the very month the AI moment happened.

And the timeline that matters most for this page: the security buildout that now fills these docs began on Friday, September 4, 2026 — the two-week mark lands this Friday, September 18. Within the opening week, the SecMesh defense engine, the seeded moving-target auto-defense, the 69-trial baseline, and the whole entanglement fabric over E91 were all conceived and shipped; they have been hardening since. That is the honest denominator for every claim you read in this repository.

Alongside the code, the writing: since March 10 this operator has been posting on X by hand — roughly 25,000 tweets and replies across @wreckmyshit and @boogersandcheez, arguing with, learning from, and getting corrected by the tech sphere at large. Most of the ideas that landed in these repos were first stress-tested at volume in that feed. The archive is kept on the e200ha; this page credits it rather than linking it.

Receipts for the dates on this page are the repos themselves: github.com/BoogerCheeseOnRye (creation timestamps via the public GitHub API). Nothing here is a claim without an artifact behind it.

Why it matters — the thesis

The same people who get impressed by the live previews have told me in person, repeatedly, that this is beyond the status quo for someone coming into the field cold. I agree with the *direction* of that statement but I want to be precise about where the bar actually is:

  • The concept is the product. The physics engine is built on an honest-approximation contract: it never pretends to be real matter, it states the approximation it makes and then holds itself to it. That same contract extends to the security layer — the SecMesh baseline (69-trial measured table in guide.html), the per-rotation-seeded moving-target auto-defense, and the entanglement fabric that runs a real E91 key-agreement protocol across your phones with Bell-CHSH detecting an injected Eve via S < 2.
  • Everything is measurable. The repository ships a 20-probe self-test gate in selfcheck.mjs (20/20 green at the time of writing — physics, exports, shared-engine sync, real defense A/B, E91 fabric, agent pen, PQ-hybrid TLS, novel-vector sweep). The white-paper numbers in the guide — admission S ≈ 2.83, eve S ≈ 0.6, patch/pressure pairs, rotation-vs-intercept curves, the 5-node conference key — are measured, not asserted.
  • No infrastructure, no excuses. The entire thing is three static pages of vanilla ES modules, vendored three.js, zero dependencies at runtime, zero build step. It demos in the browser you already have.

Scoping it honestly

Six weeks in, this is a proof-of-honesty, not a deployed product. The quantum channel is emulated (photons don't travel over wifi), and the cluster's physical deployment is limited to the phones in reach — not Cloudflare's network. The claim here is conceptual parity: the logic of entanglement-based key agreement, detectable eavesdropping, and conference keying runs end-to-end on real hardware. The deployment layer is a packaging and control-node problem, not a research problem — and it is already being worked (see guide §4g).

Working method

Agent-assisted, personally directed. The AI writes a lot of the keystrokes; the intent, the architecture calls, the honest-approximation framing, and the "what would this actually prove?" bar are mine. Teaching code on paper taught me the grammar of a program long before any AI existed — that grammar is what separates a repo that demos from a repo that argues.

Gates over vibes. Every subsystem earns a probe; every probe runs as part of a single self-check entry point. If the number stops being green, the change isn't done.

Docs are part of the build. Every finding lands in the repository twice — prose in readme.html, white-paper tables in guide.html — so a stranger (or a future hiring manager) can read the reasoning without running a single command.

Deployment posture. The target host is whatever is in reach — this device, a phone, an always-on control node. The system is designed so that "more nodes" is a config line, not a rewrite.
